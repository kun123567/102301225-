## 0-bis 浮层的处理：不删，抬到最上层 + 白底垫（按你选的方案）

指针气泡（`hi / lo / mid / i / j / cur / top / p / head`…）、区间框与区间标签、结点角标都是**图内标注**，删了就丢语义；
它们的坐标来自 add01 原始布局（气泡在格子上方 14px、角标在结点框外 12px、区间标签落在格子底边），
密集布局下必然与格子边框/焦点框相压。按你选的方案改成：

| 处理 | 实现 |
|---|---|
| **抬到最上层** | 浮层图元 `z = 1000`；结构图元只有 `z = 0~3`，`paint2D` 按 z 升序绘制 → 浮层一定盖在上面 |
| **白底垫（描边断开）** | 每个浮层下面垫一块白色圆角矩形（`z = 999`，chip 比自身大 6px、文字比自身大 8px，白色填充 + 白色粗描边），把被压住的格子边框从视觉上"切断" |
| **可选的纯结构图** | `stage.render(layers, { hideOverlay: true })` 仍可一键隐藏全部浮层（开关保留，默认关闭） |

代码在 `app/canvas-stage.js`：`OVERLAY_KEYS` / `haloOf()` / `raiseOverlays()`，由 `stage.render()` 调用；
`metrics()` 现在多返回一个 `raised` 计数（被抬升的浮层个数），供自检与排查用。

自检（`node tools\smoke-shell.mjs`，12 条全绿）里的相关断言：

```
✓ 浮层默认不过滤（格子 + 指针气泡 + 区间框 全保留）
✓ 指针气泡被抬到最上层（z=1000，结构图元 z≤3）
✓ 气泡下面垫了白底（z=999，fill=#ffffff），压住的格子边框会被断开
✓ 区间框同样抬到最上层（线条类不垫底，只抬 z）
✓ 窗口渲染已抬升浮层：累计 50 个图元被抬到最上层（含白底垫）
```

## 1. 找到的 6 类问题（现象 → 根因 → 修法）

### P1 图标重叠：ASCII 文本被塞进 30×30 的图标盒

- **现象**：时间轴 5 个按钮里的符号挤在一起、和相邻按钮粘连。
- **根因**：`viz-window.js` 上一版用文本 `||<` `<` `▶` `>` `>|` 当图标；而 add02 的 `window.css` 里
  `.vizwin .tl-btn{width:30px;height:30px;padding:0}` 是给**13×13 SVG** 设计的（`.tl-btn svg{width:13px;height:13px;fill:currentColor}`），
  3 个字符在 30px 里必然溢出。
- **修法**：照抄 add02 的 5 个 SVG 图标（`reset/prev/play/next/last`），每个按钮补 `title` 与 `aria-label`。

### P2 播放按钮没有强调色 → "看不出哪个是播放"

- **现象**：播放键和上一步/下一步长得一样，语义不明。
- **根因**：add02 的强调色规则是 `.vizwin #playBtn{background:accent}`，**按 id 命中**；我的模板没给 id。
- **修法**：播放按钮加 `id="playBtn"`；并在 `app.css` 里补 `[aria-pressed="true"]` 的按下态样式，暂停/播放状态可见（窗口 `setStep` 会更新 `aria-pressed` 与 `title`）。

### P3 时间轴刻度错位 + 步数计数无样式

- **现象**：刻度挤成一坨/不显示，`N / M` 与按钮挤在一起。
- **根因**：add02 的 `.tl-ticks{display:flex}` 要的是 `.tl-tick`（`flex:1`、内含 `.tl-dot`/`.tl-label`）子元素；
  我生成的是裸 `<i style="left:%">`，在 flex 容器里绝对定位无效 → 位置全错。另外 `.tl-count` 这个类 **add02 的 CSS 里没有**。
- **修法**：去掉"假刻度"，只保留 `.tl-playhead`（按 `left:%` 定位，规则本来就有）+ `N / M` 计数；在 `app.css` 里给 `.tl-count` 定样式（等宽、`min-width`、右对齐，1100px 断点收窄），不再挤压按钮。

### P4 画布被标题/提示压住（"重叠"的另一处真因）

- **现象**：画布左上角出现压字、图形被挡。
- **根因**：add02 的 `.viewport-head` 是 `position:absolute; top:12px; z-index:4`，`.viewport-hint` 是 `bottom:12px`，
  而 `.viewport-body{position:absolute; inset:0}`，我的 canvas 又是 `width/height:100%` → **画布图元从 y=0 开始画，直接压在标题/提示下面**。
- **修法**：`.viz-host .vizwin .viewport-body{padding:36px 14px 30px}`（画布缩进到标题/提示之间）；
  并把"本步解释"从画布里移出去 —— 新增 `explainHost` 选项，落到右栏 `#explain`（原来那个 `[data-viz-explain]` 在 add02 的 CSS 里也没有对应规则，会飘在画布上）。

### P5 重复：两套播放控制 / 六处标题 / 两个徽标 / 一个语义重复按钮

- **现象**：一屏里两排播控、同一信息反复出现。
- **根因**：
  1. 页面控制条有 `上一步 / 播放 / 下一步`（`#prev-btn/#play-btn/#next-btn`），**同时**窗口时间轴还有 `reset/prev/play/next/last`；
  2. 标题六处：`#crumb`、`#crumb-sub`、`.win-title`、`.win-sub`、`.vh-title`、`.vh-sub`；
  3. 顶部两个常驻徽标：`#engine-meta`（渲染器）与 `#convert-note`（换算提示）；
  4. `.bl-btn[data-viz-replay]`（重播）与时间轴 `reset`（回到第 1 步）**行为相同**。
- **修法**：
  1. **删掉页面控制条里那三个按钮**，播控只在窗口时间轴里有一套；速度滑条保留在控制条（它是唯一无重复的参数）；
  2. 标题收敛为三层且各说一件事：`#crumb`（案例）+ `.win-sub`（变体/样例）+ `.vh-title/.vh-sub`（结构/画法）；
  3. `#engine-meta`/`#convert-note` 移入右栏"渲染信息"面板，不再和案例标题抢顶部空间；
  4. 删掉"重播"按钮（reset 已覆盖）。

### P6 窗口可拖拽缩放手柄 / 光标与实际不符

- **现象**：窗口右下角出现 resize 手柄（拖动会拉伸画布变模糊）；标题条显示"抓手"光标但拖不动。
- **根因**：add02 的 `.vizwin{resize:both; }` 与 `.win-bar{cursor:grab}` 是为"浮动窗口"设计的；本项目窗口是**内嵌固定高**。
- **修法**：`app.css` 里 `.viz-host .win.vizwin{ resize:none; position:relative; inset:auto; height:560px }`，
  `.win-bar{cursor:default}`。

### 顺带修掉的"表意"问题

| 位置 | 之前 | 现在 |
|---|---|---|
| `viewport-hint` | 「拖拽平移 · Ctrl + 滚轮缩放 · Home 复位 · **全部画法来自 add01 的 9 个 renderer**」（暴露实现） | 「拖拽平移 · Ctrl + 滚轮缩放 · Home 复位」 |
| 右栏"渲染信息" | 顶部徽标挤在案例名旁 | 独立面板：`渲染器 TOneArrayForm（style 1 / backend canvas）` + 换算说明 |
| 控制条 | `结构`/`画法` 无解释 | 每个 `.lbl` 加 `title`（结构=这个案例用到的族；画法=同族其它画法，有损换算） |
| "怎么用"面板 | 无 | 新增：选了案例→变体/样例→结构/画法→时间轴播放，含快捷键 |

# 追加轮二：树的排布（你截图那棵"平衡二叉树"）

## A. 看到的现象与真因

截图里 `平衡二叉树`（style 9 / TTreeForm canvas 后端）：结点 3→2→1 竖着摞成一条线、`bf=` 气泡贴着圆、`L` 标签挤在中间。真因在 `vendor/engine/renderers/tree.js`：

1. **不可达结点没被赋 x**：`px()` 里 `xs.get(id) ?? 0` → 全部落在 `(500,62)`，多个圆完全重合（33 层，B 树的"提升键"最明显）；
2. **单孩子取中点＝孩子本身**：一条链就画成一条竖线（70 层，AVL/红黑树/重建）；
3. 父结点的 `h=xx` 文字与孩子的 `bf=` 气泡之间只有 **0.7px**，`L`/`R` 标签没有落点。

## B. 修法（`app/canvas-stage.js › polishTreeCanvas`，仍是纯坐标后处理）

| 规则 | 效果 |
|---|---|
| 不可达结点当额外根参与 tidy | B 树的 叶/叶/提升键 变成横排，不再叠死 |
| 单孩子朝反侧偏 0.6 格 | AVL 的 3→2→1 变成左下台阶，看得出"左左链" |
| 同深度最小间距 `r1+r2+18` + 整组居中 | 结点不再相切，树居中 |
| `levelGap = (h-110)/depth`（≤110） | 行距拉开，`h=xx`/`bf=`/`L` 三者各有落点 |
| badge · 边标签 · 指针气泡 两轮互相让位 | badge 回到正上方，`L`/`R` 落到边侧 |
| 指针气泡"绕结点找空位 + 箭头指入" | 不再悬空、不再盖住别的结点 |

## C. 量化


# 十二、图里那两根"莫名其妙的小短线"——根因在 **DOM 原点**，不在排版

## A. 症状（用户连着四次说"还是不行"的那两根线）

`b/prim`（Prim，style 10，卡片 432×262）画面上：

- A 结点左下方多出一小截**斜/竖的短线**，哪条边都不属于它；
- C 结点**左边**多出一截**水平灰线**，一直伸出结点之外；
- 而 B–C 之间本该有的那条边**不见了**；
- `?debug=1` 的 `console.table` 里每个元素都 `inFrame: true`，`stray-audit` 扫 prim 也是 0 命中。

## B. 根因：线段的包裹层原点写成了 `min(x1,x2)/min(y1,y2)`

`app/prim-dom.js › originOf()` 早期版本：

```js
if (p.kind === 'line') return { x: Math.min(p.x1, p.x2), y: Math.min(p.y1, p.y2) };  // ← 错的
```

线段的局部几何是**"水平段 `(0,0) → (len,0)`，绕原点旋转 θ"**，所以原点**必须是真实起点 `(x1,y1)`**。
只有"左→右、上→下"画的线，`min` 才恰好等于起点；反过来画（或斜着从右下往左上画）时，旋转中心偏到另一头，
整根线被搬到别处 —— 屏幕上就是**一根错位的短线，而原位置空了**。

对照 `b/prim` 第 3 步的真实数据（`tools/prim-dump.mjs b/prim v1 3 --style 10`）：

```
line e-B-C  568.1,208 -> 431.9,208     ← x1 > x2：旧代码原点=431.9，旋转 180° → 画到 295.7..431.9（C 左边）
line e-A-C  489.0,71.1 -> 420.9,188.9  ← x1 > x2：旧代码原点=420.9,71.1，θ=120° → 画到 A 左下方的短斜线
circle n-C  c=409.9,208 r=22
```

## C. 为什么前三轮都"验不出问题"

之前所有审计（`overlap` / `visual` / `tree` / `stray` / `dom-leftover`）量的都是 **prim 数据**或**元素个数**：

- prim 数据里 `e-B-C` 的坐标**完全正确**，所以几何审计 0 命中；
- DOM 里元素个数**完全正确**，所以残留审计 0 命中；
- `?debug=1` 打的是**键名/transform 字符串**，不是"实际落在哪"，所以表里也没异常。

**缺的是"数据 ↔ DOM 一致"这一层断言。** 补上 `tools/dom-geometry-test.mjs`：渲染后从 `<g>` 的
`transform` + 子元素反推绝对几何，与 prim 逐项比对（54 案例 / 40,595 图元 / 容差 0.75px）。
把 `originOf` 改回 bug 版本，这个门禁立刻报 **354 处**不符，其中就有用户截图里的那两条：

```

✗ b/bfs step3 key=e-C-A 终点 (439,-18.34)≠(439,71.05)
```

## D. 顺手修掉的第二个 DOM 层 bug：Z 序漂移

复用元素时 `<g>` 还停留在上一帧的文档位置，于是"谁先创建谁在下"决定层级——遮挡关系会随历史漂移。
现在每帧按 `z` 排好的顺序**对齐文档顺序**（顺序真的变了才重建，没变一个字都不动，避免白白重启 CSS 动画）。

# 十三、那些"忽然飞起来的灰点"——整体下移漏掉了装饰物

## A. 那些点是什么

`link-2d.js`（style 3 / TLinkForm）每画一条连接线，会在**折线末端**加一个小圆做"落点"：

```js
const mid = pts[pts.length - 1];
prims.push(P.circle(`dot-${fromId}-${toId}`, mid[0], mid[1], 3.2, { fill: LINK.LinkDot /* #8a93a5 灰 */, z: 2 }));
```

所以它本来应当**正好压在箭头尖端**上（r=3.2 的灰点）。用户截图里那三个灰点就是
`dot-n0-n1 / dot-n1-n2 / dot-n2-n3`。

## B. 为什么会浮起来：`passHeader` 的"内容整体下移"漏掉了它们

窄卡片（301×217）上标题会压到 `fast`/`slow` 气泡，`passHeader` 于是把内容整体下移 `dy`：

```js
// 旧代码
const contentPrims = c.list.filter((p) => !topTitles.has(p) && !c.decos.includes(p));  // ← 排除了装饰物
```

`dot-*` 的 role 是 `decoration` → 进 `c.decos` → **没跟着平移**。实测（`e/kth-from-end` 第 0 步，301×217）：

```
before polish: 框 y=20.0   折线末端 y=42.0   落点圆 y=42.0   ← 三者一致
after  polish: 框 y=55.5   折线末端 y=77.5   落点圆 y=42.0   ← 圆被落在原地，差 35.50px
```

**整体平移是一次图层级操作，只要有元素没跟着走，它就会悬在半空。** 这是布局层的通例，不是这一个 key 的特例。

修法：下移时只保留"顶部标题"在原地，**其余全部一起走**（含轴字母、段落标题、落点圆）。

## C. 为什么 12 个审计全绿却没发现

所有审计（overlap / visual / tree / stray / dom-geometry / smoke…）都跑在 **1000×300 或 900×300**。
而这次的下移分支只在**窄且矮**的卡片上才会触发（宽卡不换行、不缺空间 → `dy ≤ 0` → 不动）。
所以：宽度不真实 = 分支没被测到。

现在的口径：

- `tools/stray-audit.mjs` 默认扫 **5 种真实卡片尺寸**（301×217 / 300×160 / 300×300 / 480×260 / 900×300）；
- 新增两条"附着不变量"：
  1. `dot-<a>-<b>` 必须贴在自己 `link-<a>-<b>` 的折线末端（容差 1.5px）；
  2. `nv-<id>` 的值文本必须落在自己的结点体（圆 `n-<id>` / 框 `nfill-<id>`）里。
- `tools/dom-geometry-test.mjs` 支持 `--w N`，301 宽下同样 40,595 个图元逐个一致。

红/绿证据：把 `passHeader` 改回"排除装饰物"，`stray-audit` 立刻报 **79 条 `落点离群`**；改回来 0 条。

# 十四、线索树的"虚线压在实线上"——线索不该和树边抢同一个出口

## A. 用户看到的

BiThrTree（中序线索化，style 9，384×300）：A 下面同时有一根浅灰实线和一根虚线，
两者从 A 附近出发、挤在一处；标题还压着右上角的"层数 3"。

## B. 那些虚线是什么（先回答"正常吗"）

`th-<from>-<to>`，`tree.js` 里 `data.threads` 画出来的**线索**：绿=后继，棕=前驱。
中序 B → D → A → C 之下：

```
th-D-B (D 的前驱是 B)   th-D-A (D 的后继是 A)   th-C-A (C 的前驱是 A)
```

**线索连到父结点是正常的**——前驱/后继本来就可能是父结点，这是数据结构决定的事实。
不正常的是**画法**：树边画成"父结点下沿 → 子结点上沿"，线索却画成"源结点中心 → 目标结点中心"，
于是两者几乎从同一点出发，在 384px 的卡片上就成了"虚线压在实线上"，谁也看不出哪条是线索。

## C. 修法（几何规则，不认案例）

`app/polish-passes.js › passThread`（全风格通用，接在 profile passes 之后）：

1. **侧面出入**：线索从结点的**左右侧边框**进出（目标在左走左侧、在右走右侧），
   把它从树边独占的"上下沿出口"上挪开；
2. **仍然压住才弯**：沿整条虚线取 9 个采样点，若 ≥35% 落在某条实线 2px 内，
   才把中点沿法向鼓出 `P.thread.bow = 13`（首尾不动，变成 3 点折线），
   方向取"离实线更远、且不撞结点"的一侧。

## D. 同屏顺手修的：标题压角标

`name` 的实际宽度 403.4px，而卡片只有 384px —— 和右上角的 `depth`（"层数 3"，340…372）必然叠字。
`passHeader` 现在：

- 标题超出可用宽度就**按比例缩字号**（下限 `P.header.minTitlePx = 10`，绝不删字）；
- 缩完仍与别的文字相交 → 把那行字挪到标题下面一行（只改 y，保持右对齐的 anchor 不动）。

实测：标题 13px → 10.5px（宽 353），`depth` 由 (372,16) → (372,30.25)，`hits = false`。

## E. 门禁（`tools/stray-audit.mjs` 新增两条不变量）

```
① 线索压实线：整条虚线 9 个采样点里 ≥35% 落在实线 2px 内 → 命中
② 线索非侧面出入：端点不在任何圆的左右侧边框上（|y-cy|≤4 且 ||x-cx|-r|≤4）→ 命中
```

红/绿：临时停用 `passThread` → **245 条线索全部命中**；恢复 → **0 条**。
`overlap-audit` 在 1000×300 / 384×300 / 301×217 / 300×160 四种尺寸下均为"无重叠"。
