## 0. 本次改动的目的（**务必先读这一段**）

### 0.1 一句话目的

> **让「任意贴进一段 C/C++ 代码」都能自动认出它用了哪些数据结构，并按正确画法可视化——而不是像现在这样：要么认不出，要么连插桩都编译不过。**

### 0.2 触发这次改动的事实（用户实测，不是假想）

用户贴进一段标准的图论 BFS 代码，代码里**明明有三样结构**：

```cpp
vector<int> g[N];   // 邻接表（数组 + 动态数组）
queue<int> q;       // 队列
bool vis[N];        // 标记数组
```

而系统当时的表现是：

| 现象 | 严重性 |
|---|---|
| 静态检测：**一项也没识别出关键结构**（`vector<T> g[N]` 不在 21 条规则覆盖里） | 识别层缺失 |
| 单步可视化：报 **「插桩版本编译失败，已回退到普通编译」** | 可视化直接不可用 |
| 用户只能"编译 + 运行"，**看不到任何结构图** | 产品核心价值归零 |

这两条正好暴露了 `PLAN.md` 里遗留的两个薄弱点：
① 识别靠"正则猜文本"；② 插桩靠"正则判断声明行"。

### 0.3 本次要达成的三件事（可验收）

| # | 目标 | 验收标准 |
|---|---|---|
| **1** | **识别从"猜"变成"查"**：类型查表（AST 声明表）+ 内存事实（运行时堆图），26 项每一项都有明确判据 | §1.2 的 10 个硬用例全过；26 项回归矩阵（§8）无"无判据"项 |
| **2** | **可视化对任意教学/竞赛代码可用**：修掉插桩编译失败，让上述 BFS 代码能单步看结构 | 该 BFS 代码 `/api/trace` 返回 `ok:true`（不再是"回退普通编译"） |
| **3** | **零配置为主、人工只做兜底**：默认自动判定；仅在"同构歧义"（三叉链表 vs 图十字链等）时给一行提示，一键采纳 | 用例 10：判错后一次点击即可修正，且下次记住 |

### 0.4 明确**不**做的事（防止范围漂移）

| 不做 | 理由 |
|---|---|
| 静态形状分析（TVLA / Infer Pulse） | 需完整 clang 前端，我们的后端是 Open Watcom；工程量为几十人年 |
| 通用 C++ 编译器前端（宏展开、多文件、模板实例化推导） | 与"教学可视化"目标不匹配 |
| 追求 100% 无人干预 | 三叉链表 / 图十字链表 / 双链树 等同构结构在代码层面**不可区分**，"手工指定"必须保留为兜底 |

### 0.5 与整体产品的关系

> `prototype01` 的卖点是"编辑器 + 编译器 + 调试器 + **可视化**"。
> 渲染器（M3）已经能在拿到正确数据后画出数组/链表/树/栈/堆；
> **本次改动解决的是"谁来告诉渲染器画什么"**——即识别层。识别不可靠，渲染器再全也发挥不出来。

> 目标：**贴入任意 C/C++ 代码 → 自动识别所用数据结构 → 按 26 项目录给出画法**，尽量零配置。
> 范围：只解决"识别"这一件事；**渲染器已具备**（数组 / 链表 / 树 / 栈 / 堆 / 单元格 全部实现并通过测试），本文件不再改动它们。

## 3. 第①层：AST 声明表（路线 D，轻量档 a）

### 3.1 做什么

把"正则猜文本"升级为"查声明表"：

```js
// web/js/ast.js（零依赖）
DeclTable: name -> {
  type: "vector<int>", baseType: "vector", inner: ["int"],
  ptrDepth: 0, dims: ["N"], isArray: true,
  structTag: null, scope: "global" | fnName, declLine: 7, initLine: null
}
StructTable: tag -> { fields: [{name, type, ptrDepth, isArray, self, offset, size}] }
FnTable:     name -> { ret, params[], start, bodyLine, end }
```

### 3.2 必须处理的五种语法（正则会错的地方）

| 语法 | 例子 | 正则为何失败 |
|---|---|---|
| typedef 别名 | `typedef struct Node *LinkList;` 后用 `LinkList head;` | 只见到 `LinkList`，不知道它是 `Node*` |
| 嵌套模板 | `vector<vector<pair<int,int>>> g;` | 贪婪/非贪婪匹配都会切错 |
| C++ 模板声明 | `queue<int> q;` | 被当作"语句"包进 `{ }` → 变量作用域被切断（**已修的 bug**） |
| 多声明符 | `int a[N], b; Node *p, *q;` | 只能抓到第一个 |
| 注释/字符串干扰 | `// vector<int> g[N]` | 误报 |

### 3.3 复用而非重写

`server/instrument.js` 里已有 `parseStructs / parseDecl / parseFunctions`（约 60% 的活）。
**把它抽成同源实现**：一份放在 `server/ast.js` 供插桩用，浏览器侧 `web/js/ast.js` 用同一份（构建时内联或复制），
避免"两套解析器给出两种结论"这种最难查的 bug。

### 3.4 附带治病（这是最高性价比部分）

插桩器改用 `DeclTable` 判断"这行是否声明"，可根治：
- `queue<int> q;` 被包进 `{ }` → `q` 作用域断裂（`E006` 一类）
- `ios::sync_with_stdio(false);` 插桩后整行匹配失效（`E341`，已用行内兜底临时压住，改成声明表后可删掉该 hack）

### 3.5 规则引擎改造

`detect.js` 改为两层：
1. **优先**：遍历 `DeclTable`，按"基类型 + 维度 + 指针层数 + struct 字段模式"匹配规则；
2. **回退**：原正则（用于宏、难解析片段）。

每条结果新增字段：`source:'ast'|'regex'`、`declLine`、`typeText`。

## 4. 第②层：运行时堆图判定

### 4.1 建图

输入是现有 trace 事件（`HA/HF/V/L/LE`）＋**新增事件**（4.3）。对每一步构造有向图：

```
节点 = 一次 malloc 的地址（或静态/全局变量地址）
边   = 指针字段 → 目标地址
指标 = 每节点 inDeg / outDeg / 是否在环上 / 层次深度
根   = 入度为 0 且被变量直接引用的节点
```

### 4.2 判定表（判定器的全部逻辑）

| 图特征 | 判定 | 补充条件 |
|---|---|---|
| outDeg ≤ 1、无环、根唯一 | `list` 单链表 | 有 `prev` 字段 → `dlist` |
| 有环且 outDeg ≤ 1 | `clist` 循环链表 | — |
| outDeg = 2（left/right）、inDeg = 1、无环 | `btree` 二叉树 | 有 `color` → 红黑；有 `ltag/rtag` → 线索树 |
| outDeg > 2，或子指针为数组 `child[]` | `mway` 多叉树 | `ptr[]/key[]` → B 树族；字符边 → Trie |
| 结点同时有 `right` 与 `down` | `cross` 十字链表 | 稀疏矩阵 / 图十字链 |
| 多根 + 任意度 + 有环 | `graph` 图 | 配合顶点数组 → 邻接表 |
| `parent[]` 数组 + 出现 `find/union` 调用 | `ufset` 并查集 | 源码侧匹配函数名 |
| 数组 + `size/top` 字段 | `seq` 顺序表 / `sqstack` 顺序栈 / `heap` 堆 | 看字段语义 |

输出：`shape` + `evidence`（`outDegHist`、`hasCycle`、`levels`、`rootCount`），供 UI 展示"为什么这么判"。

### 4.3 需要的后端扩展（三处，按优先级）

| # | 扩展 | 事件/实现 | 用途 |
|---|---|---|---|
| ②-a | **指针边事件**：dump 时把每个指针字段的目标地址发出来 | `P\|var\|fieldName\|fromAddr\|toAddr` | 建图的基础；现在 `L` 只给了 key，没有边 |
| ②-b | **STL dump 族（G）**：`vector` → `_M_start/_M_finish`；`queue/stack` → 底层 deque；`map/set` → 红黑树；`priority_queue` → 数组 | 生成测试程序探明布局后生成 dump 函数 | 让 `vector<int> g[N]`、`queue<int>` 真正可判 |
| ②-c | **静态区/全局地址**：全局数组、`vis` 的位置与长度 | 复用 `V` + 声明表 | 区分"数组结构"与"堆结构" |

> ①（2 中的 `E006`）必须先修，否则 trace 跑不起来，②无从谈起。

### 4.4 稳定性与边界

- 空结构 / 规模 < 2 → 返回 `unknown` + 提示"等结构建好后再单步"；
- 结点上限 24（与既有 dump 上限一致），环检测用 DFS 三色标记；
- 只把"地址落在已分配块（`HA` 记录）或静态区"的指针当边，避免把整数误当指针（这是唯一容易误报的点）。

## 6. 仲裁器（`web/js/arbitrate.js`）

```js
function arbitrate(varName, ast, runtime, manual) {
  if (manual)  return { ...manual, source:'manual', conf:1.0 };      // ③ 最高
  if (runtime && runtime.conf >= 0.85) return { ...runtime, source:'runtime' };
  if (ast)     return { ...ast, source:'ast' };                      // ① 兜底
  return { templateId:null, source:'none', conf:0, hint:'请在跟踪设置里指定' };
}
```

| 情形 | 处理 |
|---|---|
| ①与②一致 | conf = max(①,②)+0.05（封顶 0.99），source=`ast+runtime` |
| ①与②冲突 | 取②（运行时事实优先），并在 UI 标注"已按运行时修正" |
| 只有① | 用它，UI 标"静态推测" |
| 只有② | 用它，UI 标"运行时判定" |
| 都没有 | 显示"未识别" + 引导去跟踪设置 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 自研 AST 不完整 | 只覆盖"声明子集"，未知语法**回退正则**并记 `source:'regex'`；不追求完整 C++ 解析 |
| STL 内部布局随版本变 | 写**探针程序**（编译并运行 `sizeof/offsetof`）自动探测，探测失败则跳过 STL dump，降级为① |
| 整数被误当指针 | 只认"落在 `HA` 已分配块或静态区"的地址；双向校验指针宽度（4 字节） |
| 判定抖动（同一变量两步间形状变） | 以"最后一次成功判定"为准，UI 标"依据第 N 步" |
| 大结构性能 | 结点上限 24、步数上限 4000（既有）；环检测 O(V+E) |
| 回归风险 | 每次提交跑 `test-m2/m3/m4m5` + 新增 `test-detect.js` |

# 12. 附录：路线 D-b（tree-sitter WASM）—— 可选的强力档

> 本章补上前面"三档成本路线"里被省略的 **b. 中等**档，并把它设计成**可插拔增强**，不改动 a 档接口。
> 本章对 §7 里程碑追加 **D4（可选）**。

## 12.1 它是什么

**tree-sitter** 是一套容错、增量、可编译成 WASM 的语法解析器生成器。
把 `tree-sitter-c` / `tree-sitter-cpp` 的 grammar 编译成 `.wasm`，配上**运行时 JS（`web-tree-sitter`）**，
就能**在浏览器里拿到真正的 AST**——不需要 Node、不需要后端、不需要 clang。

```js
// 形态大致如此（示意，非最终代码）
const Parser = await WebTreeSitter();
await Parser.Language.load('tree-sitter-cpp.wasm');
const tree = Parser.parse(src);          // → 真 AST，节点带 range/类型
```

## 12.2 与 a 档（自研声明解析器）的对比

| 维度 | **a. 自研声明表**（D1） | **b. tree-sitter WASM**（D4） |
|---|---|---|
| 依赖 | **零** | 运行时 JS + 1~2 个 grammar wasm |
| 体积 | 0 | 粗估：runtime 数十 KB~数百 KB；`c` grammar 约 0.3~0.6 MB；`c++` grammar 约 1.5~3 MB（**需实测**） |
| 覆盖语法 | 声明子集（够覆盖主流写法） | 近乎完整 C/C++（含 `int (*fp[3])(void)` 这类复杂声明） |
| 容错（边写边解析） | 差（语法不完整会解析出垃圾） | **强**（容错恢复，适合编辑器实时场景） |
| 增量解析 | 无 | **有**（只重解析改动区间，onChange 不卡） |
| 复杂声明/宏 | 容易错 | 正确解析语法层；宏仍不展开 |
| 接入成本 | 低（~300 行，可复用现有 `parseDecl`） | 中（vendor wasm + 适配层 + 体积与加载策略） |
| 离线/沙箱 | 无影响 | **需要拿到 wasm 文件**；本机 shell 无法 npm install，必须手动放置或从镜像下载 |
| 许可证 | 自研 | tree-sitter 与 grammars 均为 **MIT**（需随包附 LICENSE） |

## 12.3 关键设计：**AST provider 可插拔**（这样 b 档不会推翻 a 档）

`web/js/ast.js` 对外只暴露一个接口，内部可切换实现：

```js
// 统一接口（a/b 两档共用，上层 detect.js / instrument 无感）
AVC.ast.parse(src, opts) -> {
  decls:   DeclTable,     // name -> {type, baseType, ptrDepth, dims, scope, declLine}
  structs: StructTable,   // tag  -> {fields:[{name,type,ptrDepth,offset,size,self}]}
  fns:     FnTable,       // name -> {params, start, bodyLine, end}
  provider: 'self' | 'tree-sitter',
  degraded: boolean       // true = 走了回退正则
}
```

| 情形 | 行为 |
|---|---|
| b 档 wasm 未放置 / 加载失败 | **自动回落 a 档**（`provider:'self'`），功能不变、精度下降，UI 标"静态(轻量)" |
| b 档可用 | `provider:'tree-sitter'`，UI 标"静态(AST)" |
| 两者都失败 | 回退正则（`source:'regex'`），并在结构窗提示 |

上层（`detect.js` / `instrument.js` / 结构窗）**只认 `DeclTable`**，不关心谁产的——这是本章唯一必须遵守的架构约束。

## 12.4 获取与打包（本环境的具体难点）

| 问题 | 处理 |
|---|---|
| shell 无外网、不能 `npm install` | 从以下任一来源**手动取文件**放入仓库：`web-tree-sitter` 的 `web-tree-sitter.wasm`；grammar 用预编译包（如 `tree-sitter-wasms`、`@vscode/tree-sitter-wasm` 这类现成 wasm 集合） |
| 首屏体积 | **懒加载**：默认不加载 wasm；用户打开"高精度识别"开关（或首次粘贴 >200 行）时才 `fetch` |
| 离线可用性 | 文件 vendor 进 `web\vendor\tree-sitter\`，**不走 CDN**（否则离线即废） |
| 许可证 | 目录内附 `LICENSE`（MIT），README 注明来源与版本 |

## 12.5 b 档能多做、a 档做不到的验收用例

| # | 用例 | a 档 | b 档 |
|---|---|---|---|
| 11 | `int (*fp[3])(void);`（函数指针数组） | 大概率解析错 | ✅ 正确 |
| 12 | `typedef vector<pair<int,Node*>> Graph; Graph g;`（多层 typedef + 模板嵌套） | 部分可 | ✅ |
| 13 | 语法不完整时（正在敲 `for (int i = `） | 解析出垃圾 | ✅ 容错，不误报 |
| 14 | 1000 行文件连续编辑（增量解析） | 每次全量、可能卡 | ✅ 只重解析改动区间 |

## 12.6 追加里程碑 D4（可选增强）

| 里程碑 | 内容 | 完成判据 |
|---|---|---|
| **D4** | vendor `web-tree-sitter` + `tree-sitter-c/cpp` wasm；实现 `ast.js` 的 tree-sitter provider；懒加载开关；回落逻辑 | §12.5 用例 11~14 全过；D1 的用例 1~5 在 b 档下**仍然全过**；未放置 wasm 时自动回落 a 档且功能不缺 |

## 12.7 何时该升级到 b 档（决策条件）

按优先级，满足任意两条就做 D4：

1. a 档在**真实用户代码**上解析失败率 > 10%（可用 `test-detect.js` 统计 `degraded:true` 比例）；
2. 需要**边写边实时**识别且 a 档明显卡顿或误报（编辑器体验问题）；
3. 需要支持**多文件 / 头文件包含**（b 档的 range 与查询能力更适合）；
4. 出现大量"宏定义的容器类型"（`#define Graph vector<vector<int>>`），a 档无法展开。

否则**停在 a 档**：零依赖、体积为零、可维护性最好。

## 12.8 一句话

> **a 档保证"今天可用"，b 档保证"上限更高"；两者共用 `DeclTable` 接口，所以永远不需要"推倒重来"，只需打开一个开关。**
